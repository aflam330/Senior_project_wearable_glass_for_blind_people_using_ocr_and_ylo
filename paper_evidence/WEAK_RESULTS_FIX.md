# Weak results: causes and fixes (2026-09-28)

Generated by `realtime_bangla_taka_detection/scripts/eval/write_weak_results_fix.py`. Every number is read from a saved result file; see the script header for the paths.

## Summary

- Most of the collapsed policy results were caused by evaluation bugs, not by the methods. After the fixes no policy collapses on either model (tables below).
- On the deployed prefix_ft model the plain fixed view order is the best (or tied best) policy at every view count. The learned policies (quality, confidence, diversity, CRIQP `full_proposed`) pick a weaker first view and do worse at 1-4 views; `full_proposed` with adaptive stopping stops after one view below fixed order. Learned view selection is a negative result, not a working method.
- The NaN bug also changed stored 1-6 view numbers. Several variants reported as degrading with more views (`rsqa`, `her_base`, `auxfix_stopgrad`, `auxfix_separate*`) do not degrade once it is fixed. Documents whose verdicts used those numbers carry a correction note.
- The early Q-DUIG ablations (`results/qduig/ablations`) and the early `proposed` model remain weak after the fixes. They come from an unstable 4-6 epoch recipe and are superseded by `results/qduig/ablation_prefix`; they must not be presented as working methods.
- CAMVA's single-seed result holds over three seeds: better than the baseline only at six views, much worse at one to five.

## Evaluation bugs that were fixed

1. **Sequential policies and the oracle skipped the view self-gate.** `sequential_predict` and `run_oracle` rebuilt the model from `encode_views`, `_quality` and `fuse_prefix`, but `forward()` also applies `nan_to_num` and `z * (1 + tanh(view_gate(z)))`. Models trained with `view_self_gate` (prefix, prefix_ft, the prefix ablations) were scored on features they never saw. Both now call `QDUIGNet.view_features()`.
2. **NaN for fully confident notes.** `binary_entropy_t` clamped with eps = 1e-8, and in float32 `1 - 1e-8 == 1.0`, so p = 1 gave `0 * log 0 = NaN`, which reached the HGEF logits. `forward()` replaced NaN logits with 0 (p = 0.5, read as genuine); the sequential path left them NaN (read as counterfeit). 23 of 208 test notes were affected for prefix_ft seed 42. eps is now 1e-6.
3. **Masked views changed the volume feature.** `logdet_gram` gave every masked-out view log(tau) = -4.6, so one selected view inside six slots read -20 instead of about 0. The policies and any padded batch therefore saw a different context than a plain k-view test loader. Masked views now contribute log 1 = 0; logits from masked and cut-down inputs agree to 5e-6.
4. **The random policy was not seeded** after its first pick (`torch.rand_like`). It now uses the seeded generator.
5. **Old Q-DUIG checkpoints no longer loaded** (`view_gate`, `k_bn` added later). They load again when those layers are switched off in their config.
