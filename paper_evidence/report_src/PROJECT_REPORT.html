Savior Glass

An assistive smart glass for blind and low-vision users in Bangladesh, with Bangladeshi Taka recognition and counterfeit (jaal) research
Project report · 2 October 2026 · Repository branch RPi5_deploy (latest commit f24c93b8) · Every number below comes from a result file in the repository (claim registry: 298 claims, all pass the value check)

1. Summary

Savior Glass is a wearable camera glass built on a Raspberry Pi 5. It speaks in Bangla and English through bone conduction. It can:

  • read printed text aloud;
  • name objects around the user;
  • recognise Bangladeshi Taka notes and give a safe genuine-or-check answer for 500 and 1,000 Taka;
  • use an online vision model when the internet is available.

The research side has three parts:

  • the counterfeit problem on the JaalTaka dataset;
  • a watermark-based check that works on counterfeit prints the model has never seen;
  • an OCR benchmark with correctly shaped Bangla text.

Main results

  • Taka detector: mAP@0.5 0.995 on 2,282 test images, and 91.5 % correct on 1,536 independent real photos.
  • Counterfeit check, unseen prints: 95.0 % (3 seeds, 6 views) with the watermark hybrid.
  • OCR, held-out test: character error 9.3 % → 2.4 %; Bangla 11.9 % → 3.2 %.
  • Safety: the glass never says "counterfeit". 0 of 88 test counterfeits were passed as genuine.
  • Raspberry Pi 5: currency check 327 ms median; 30 minutes with no throttling (peak 77.1 °C).

Main findings

  • JaalTaka's usual split lets the same counterfeit print appear in training and test. It is a reprint test.
  • On truly unseen prints, accuracy drops from about 98 % to about 90 %. The banknote watermark recovers about 5 points.
  • Earlier Bangla OCR tests used wrongly drawn Bangla (no text shaping). They were redone.
  • Remaining gains need data: more counterfeit prints, glass-camera photos and a user study, not more models.

2. Problem statement

  1. Daily independence. Blind and low-vision people in Bangladesh cannot read signs, labels, medicine packets or prices without help, and cannot always tell which note they are holding. Most assistive tools are English-first, need an internet connection or a phone in the hand, and do not read Bangla.
  2. Counterfeit notes. Counterfeit 500 and 1,000 Taka notes circulate, and a blind person cannot feel a watermark. A wrong "genuine" answer costs money. A wrong "counterfeit" answer can cause a public accusation. A device must therefore be safe before it is clever.
  3. Evaluation is misleading. Published counterfeit results on JaalTaka look near-perfect. But counterfeits printed from the same plate share one serial and appear in both training and test, so the number measures recognition of known reprints, not new counterfeits.
  4. Bangla OCR is fragile. Bangla script has conjuncts and vowel signs that move around the consonant. Off-the-shelf OCR is weaker on Bangla than on English, and synthetic test images are easy to draw wrongly.
  5. Small hardware. All of this has to run offline on a Raspberry Pi 5 inside a glass frame, within a few hundred milliseconds, without overheating.

Findings:

  • Prefix training removes the one-view collapse of fixed-view training (McNemar p down to 10-22) and makes results stable across seeds.
  • Frozen ImageNet backbones match it on this split: 60 paired tests, none significant. So no state-of-the-art claim is made on JaalTaka.

Findings:

  • Accuracy drops by about 8 points when counterfeit prints are truly new.
  • The watermark brings it back to 95 % and is stable across seeds.
  • The hybrid ties a properly fine-tuned ResNet-50. It does not significantly beat it: there are only about 24 distinct test prints.
  • A serial blacklist catches 0 of 19 unseen-serial counterfeits.

    • text-region selection, the largest gain;

6.8 Theory

  • Theorem 8 (safe threshold). With the threshold set at the highest of n validation counterfeit scores, the probability that a new counterfeit passes is 1/(n+1). For n = 88, that is 1.1 %.
  • Theorem 9. Under a distribution shift the pass rate grows by at most the total-variation distance.
  • Theorem 10. The quality gate's false-rejection bound.
  • Proposition 11. Fixed-view training does not identify the few-view predictor, which explains the seed instability.
  • Theorem 16. The effective test size is the number of prints, not notes.

8. Limitations

  • Counterfeit results rest on about 24 distinct counterfeit prints in the unseen-print test. The uncertainty is about ±12 points at the print level.
  • Whole-note counterfeit checking on the glass is not proven. The model was trained on close-ups, so the glass is set to be safe rather than decisive.
  • OCR numbers come from rendered text. Real signs, glare and curved packets will be harder.
  • Detector accuracy drops on hand-held close-ups (NSTU, 18.5 %).
  • No user has worn the glass yet in a study.

9. Research questions

  1. RQ1. How much does counterfeit-detection accuracy fall when every test counterfeit comes from a print never seen in training, and what is the right unit of evaluation: notes, serials or prints?
  2. RQ2. Can a physical security feature (the transmitted-light watermark), found by a learned localizer, generalise to unseen prints and to a second currency better than a fine-tuned whole-note CNN?
  3. RQ3. Does training on random prefixes of views (1 to k) remove the accuracy collapse that fixed-view multi-view models show when fewer views are available, and does this hold beyond banknotes (MVP-N, ModelNet)?
  4. RQ4. Can an assistive device give provably safe counterfeit feedback, with zero "counterfeit" accusations and a bounded chance of passing a counterfeit, while still being useful to blind users?
  5. RQ5. Does guided capture (spoken prompts to hold the note to the light, rejecting dark or blurry frames) reduce the time per note and the number of "check by hand" answers for blind and low-vision users?
  6. RQ6. Which parts of a Bangla OCR pipeline matter most for scene text read by a wearable camera: detection and region selection, preprocessing, recognizer fine-tuning, or language post-processing?
  7. RQ7. How far can a multi-function assistive system (OCR, objects, currency, counterfeit check) be pushed on a Raspberry Pi 5 within latency, memory and thermal limits that a wearable needs?
  8. RQ8. How large must a print-disjoint counterfeit dataset be, in prints, to show a significant difference between two detectors?
